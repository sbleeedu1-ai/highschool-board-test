# 02: 공지 목록 보기

**What to build:** 방문자가 첫 화면에서 공지 목록을 최신 등록순으로 10건씩 보고, 페이지 번호로 이동한다. 페이지 번호는 주소에 남아서 새로고침하거나 공유해도 같은 페이지가 보인다. 공지가 없거나 페이지 번호가 이상해도 화면이 깨지지 않는다. 공지 표가 처음 생기므로 CI가 실제 PostgreSQL로도 마이그레이션을 확인하기 시작한다.

**Blocked by:** 01 (걷는 뼈대)

**Status:** ready-for-agent

명세 사용자 이야기: 1-10, 16, 21-23, 67, 69-70, 72

- [x] 공지 표가 Flyway 마이그레이션으로 생기고, JPA는 `validate`만 한다(H2는 PostgreSQL 호환 모드)
- [x] `local` 프로필은 H2 파일 DB를 써서 재시작해도 데이터가 남는다(파일은 git 제외)
- [x] `GET /api/notices?page=N`: 10건, 작성일시 내림차순(같으면 식별자 내림차순), 현재 페이지·전체 페이지 수·전체 건수 포함
- [x] 페이지 번호가 숫자가 아니거나 1보다 작으면 1페이지, 범위를 넘으면 빈 목록
- [x] 목록 화면: 제목과 작성 날짜(`YYYY-MM-DD`, 한국 시간), 페이지 번호와 [이전]·[다음], 주소에 `?page=N` 반영
- [x] 공지가 없거나 범위를 넘으면 "공지가 없습니다"와 [첫 페이지로]
- [x] 서버·네트워크 오류 시 "잠시 후 다시 시도해 주세요"와 [다시 시도]
- [x] 휴대폰 폭에서도 목록이 읽기 좋다
- [x] HTTP API 테스트: 정렬, 10건 나눔, 잘못된 번호, 범위 초과, 빈 목록, 페이지 정보
- [x] Vitest: 페이지 번호 해석 함수, 날짜 형식 함수(UTC를 한국 시간으로)
- [x] CI: PostgreSQL 서비스 컨테이너로 Flyway 마이그레이션 실행과 서버 기동을 확인하는 단계가 추가된다
