# 06: 공지 수정

**What to build:** 로그인한 관리자가 공지 상세의 [수정]을 눌러 기존 내용이 채워진 화면에서 고치고 저장하면, 공지 상세로 돌아가 수정일시가 표시된다. 공지 목록의 순서는 바뀌지 않는다. 이미 삭제된 공지를 고치려 하면 안내를 받는다.

**Blocked by:** 05 (공지 등록)

**Status:** ready-for-agent

명세 사용자 이야기: 3, 48-53

- [ ] `PUT /api/notices/{id}`(관리자만): 등록과 같은 입력 검사. 수정일시를 시계 값으로 기록한다. 없으면 404
- [ ] 로그인했을 때만 공지 상세에 [수정] 버튼이 보인다
- [ ] 수정 화면 `/admin/notices/:id/edit`: 기존 내용을 채워 두고, 등록과 같은 글자 수 표시·안내
- [ ] 저장 후 공지 상세로 이동하고 `· 수정 …`이 표시된다
- [ ] 작성 중 로그인이 만료되면(401) 로그인 화면으로 이동하고 내용을 잃을 수 있다고 안내한다
- [ ] HTTP API 테스트: 수정 성공, 수정일시 기록, 목록 순서 불변, 미로그인 401, CSRF 없음 403, 없는 공지 404, 경계값, 나중 저장 우선
