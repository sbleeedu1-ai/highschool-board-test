# 08: 비밀 헤더와 로그인 잠금

**What to build:** 운영에서는 모든 API 요청이 Pages Functions를 거쳐, 방문자 IP와 비밀값을 단 채로 백엔드에 도착한다. 백엔드는 비밀값이 없는 직접 요청을 거절한다. 같은 IP에서 로그인에 5번 연속 실패하면 그 IP만 10분 동안 로그인 잠금하고, 다른 IP의 관리자는 영향을 받지 않는다(ADR-0003). 로컬에서는 비밀 헤더 검사가 꺼져 있다.

**Blocked by:** 04 (관리자 로그인·로그아웃)

**Status:** ready-for-agent

명세 사용자 이야기: 34-38, 60-61

- [x] Pages Functions가 `/api/*`를 백엔드로 전달한다. 핵심 로직은 "들어온 요청 + 설정값 → 백엔드로 보낼 요청"을 만드는 순수 함수 하나다
- [x] 이 함수는 경로·쿼리·메서드·본문·쿠키·CSRF 헤더를 그대로 옮기고, `X-Client-IP`(방문자 IP)와 `X-Proxy-Secret`을 붙인다. 방문자가 보낸 같은 이름의 헤더는 덮어쓴다
- [x] 백엔드 주소와 비밀값은 Pages 환경변수로 받는다. 백엔드 응답(상태 코드·쿠키)은 그대로 돌려준다
- [x] 백엔드: 비밀값이 없거나 틀린 요청은 403. Actuator 상태 확인만 예외
- [x] 백엔드: 비밀값이 맞을 때만 `X-Client-IP`를 믿는다. IP별로 5회 연속 실패하면 10분 잠금(429, "잠시 후 다시 시도해 주세요"), 성공하면 그 IP의 실패 횟수를 초기화한다. 기록은 메모리에만 둔다
- [x] `local` 프로필에서는 비밀 헤더 검사를 끄고, IP는 실제 접속 주소를 쓴다
- [x] Vitest: 요청 변환 함수(헤더 부착, 원래 요청 보존, 가짜 헤더 덮어쓰기)
- [x] HTTP API 테스트: 비밀 없음·틀림 403, 상태 확인 허용, 같은 IP 5회 실패 후 429, 다른 IP는 로그인 가능, 시계를 10분 앞으로 돌리면 해제, 성공 시 초기화
