# 작업 인계 — 이 저장소만의 규칙

절차는 개인 설정의 `handoff` 스킬(Claude·Codex 공통)을 따른다. 이 파일은 그 스킬에 더하거나 바꾸는 **이 저장소만의 규칙**이다. 둘이 다르면 이 파일이 우선한다.

## 기록 문서의 역할

| 문서 | 역할 |
|---|---|
| `HANDOFF.md` | 지금 상태(매번 다시 쓴다) |
| `HISTORY.md` | 시간순 기록, 사용자가 고른 것을 말 그대로 인용(덧붙이기만 한다) |
| `docs/adr/` | 되돌리기 어려운 결정의 이유 |
| `.scratch/` | 명세와 티켓(무엇을 만드는가) |
| `CONTEXT.md` | 용어집 |

## 어디서 읽고 쓰나

- `HANDOFF.md`·`HISTORY.md`는 **작업 브랜치**에서 고치고 함께 커밋한다. PR이 병합되면 `main`으로 간다. `main`의 것은 오래되었을 수 있다.
- 이어받을 때는 `git pull` 대신: `git fetch` → `gh pr list`로 열린 PR과 최근 작업 브랜치 확인 → 그 브랜치에서 `HANDOFF.md`를 읽는다.

## 커밋할 때마다

- `HANDOFF.md`를 최신 상태로 다시 써서 함께 커밋한다. 결정·변경이 있었으면 `HISTORY.md`에도 새 항목을 덧붙인다.
- **작업 브랜치 푸시는 확인 없이 한다**(사용자가 미리 허락함). PR 생성·`main` 병합은 매번 확인받는다. `main` 직접 푸시는 GitHub 브랜치 보호로 막혀 있다.

## 병합한 뒤

- 사용자가 `main` 반영을 지시한 브랜치는 병합이 끝나면 확인 없이 로컬·원격 모두 삭제한다: `git branch -d <브랜치>`, `git push origin --delete <브랜치>`, `git fetch --prune`.
- 병합되지 않은 브랜치는 지우지 않는다(`git branch -d`는 병합된 브랜치만 지우므로 그대로 쓴다).
